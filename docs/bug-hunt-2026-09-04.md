# Bug hunt — 2026-09-04

Findings from driving the app headless in Chromium (desktop 1366×768 with a Windows
UA, classic scrollbars on; iPhone 13 portrait and landscape; OS dark scheme; a
mocked clock across the 3am reset, a week rollover and both DST edges) plus a
read-through of every module. Baseline: `tests/` is green (1045 checks), no
`pageerror` on any route, no horizontal page scroll on any route, no XSS from
titles (`h()` text nodes only), `javascript:` links refused, corrupt or odd
`localStorage` boots clean. Everything below is what broke.

Tags: **[browser]** seen live · **[code]** traced through the exact path (line
numbers quoted). Severity: **DATA** loss · **WRONG** result · **UX** · **LOW**.

For the fixer: house rules in `CLAUDE.md` apply — bump `VERSION` in `sw.js` and
add the release to `js/changelog.js` in the same commit, keep `/tests/` green,
build DOM with `h()`, no dirty flags in sync. `CLAUDE.md` itself is stale: it says
`planner-v44`, `sw.js` is `planner-v47`.

## 1. Data loss

### 1.1 Erase / Restore-replace tombstones the whole account [code] DATA
`js/views/settings.js:386-391` removes only `semesterPlanner.v1`; the cloud
baseline (`semesterPlanner.cloudBase.<uid>`, `cloudSchema.<uid>`) and the
session survive. `js/store.js:1106` `importJson(..., {merge:false})` does
`Object.assign(state, next)` and never touches the baseline either. On the
next sync `winner()` (`js/cloud.js:440`) calls every row the baseline still
lists "deleted here", and `push()` (`:478-483`) sends a tombstone for each;
`planner_rows_keep_newest` lets deletes through. Every device empties.
Repro: cloud on → Erase all data → re-enter URL/key → sign in → other device
empties. Or: Restore a day-old export → everything since is tombstoned.
Fix: both paths call `resetLocalSyncState()` first; Erase removes every
`semesterPlanner.*` key. Say so in the Restore dialog.

### 1.2 Switching one occurrence's mode wipes the series' `dueTime` [code] DATA
`js/store.js:627-646` `patchOccurrence`, from `js/editor.js:187-193` `toMode`
with `scope='one'`. The patch `{plan:{…}, due:null, dueTime:null}` is folded
in key order: `plan` sets `ov.date`, `due:null` then nulls it, and `dueTime`
is not in `OCCURRENCE_OWNS` so it lands on the parent. Result: the occurrence
is unchanged, `ex` holds junk, and every occurrence loses its time. The
reverse direction (planned → Deadline) does nothing to the block and writes
`plan:null` junk (`store.js:633` only handles truthy `plan`).
Fix: let an exception own `plan`/`due` wholesale and honour them in
`occurrenceOf`, or force "this and after" for a mode change.

### 1.3 New edit after Undo leaves Redo live; Redo discards the edit [code] DATA
`js/store.js:151-158` `remember()`: the coalesce early return runs before
`redoStack.length = 0`. Edit A, edit B, Ctrl+Z, edit C within 800ms of B →
Redo still works and throws C away. Fix: clear `redoStack` before the return.

### 1.4 Deleting an area hides its notecards for ever [browser] DATA
`js/store.js:880-888` `deleteArea` re-homes items, links, sprints — not
`state.cards`. `unfiledCards` is `!c.areaId`, so a card keeps a dead id and
is on no screen. Seen: card `['note in cs','a-cs']` after delete, not on
Overview. Fix: null `areaId` on the area's cards.

### 1.5 Toast Undo after a delete puts the row back with its old clock [code] DATA
`js/editor.js:435-443`, `:448-459`, `js/app.js:255-258` push the old snapshot
back without stamping `updatedAt`; the server has a newer tombstone, refuses
the row, and the next full sync deletes it here too. `undo()` in the store
stamps (`store.js:184-188`); these do not. Fix: stamp what these Undos put
back, or route them through `upsertItem`.

### 1.6 Notes and habit edits carry no clock [code] DATA (silent, small)
Nothing sets `notes[date].updatedAt` (`note()`, `setJournalEntry`
`store.js:934-941`, `carryForward` `:980-989`, Overview `oninput`);
`rowStamp('note')` is null so `cloud.js:473` invents `now` at push — the one
thing CLAUDE.md says push must never do. A week-offline laptop overwrites the
phone's newer journal. `updateHabit`/`reorderHabits`
(`js/store/habits.js:50-69`) never stamp either. Fix: stamp in every writer.

### 1.7 Merge import silently drops links, wishlist, sprints, `habitLogAt` [code] DATA
`js/store.js:1102-1121`; `Object.assign(state.notes, next.notes)` also
replaces same-day notes wholesale. The dialog promises "adds anything new".

## 2. Sync correctness (cloud.js / gcal.js / canvas.js)

### 2.1 Paged pull skips rows sharing a `synced_at` [code] WRONG
`js/cloud.js:392` `.gt('synced_at', cursor)`, `:413` cursor = last row's
`synced_at`, `PAGE = 500`. Push upserts 200 rows per statement and
`planner_touch` stamps the transaction time, so a batch shares one
`synced_at`; a page boundary inside a batch loses the rest of it. Any full
pull over 500 rows (second device, Rebuild sync, schema bump) is missing
rows until they change. Fix: keyset-page on `(synced_at, kind, id)` or page
with `gte` and dedupe.

### 2.2 Cursor advanced past another device's write [code] WRONG
`js/cloud.js:338` takes the max of pulled and pushed cursors. A row written
elsewhere between our pull and our push has `pulled < synced_at < pushed`
and is never pulled. Fix: drop `pushed.cursor` from the cursor maths.

### 2.3 Daily Canvas refresh un-schedules assignments and re-stamps every row [code] WRONG
`js/canvas.js:175-186` always sends `plan:null` and always calls
`upsertItem`, which stamps `now` (`store.js:659`). An assignment the user
dragged onto the calendar is a bare deadline again every morning, its Google
event orphaned; an unchanged import beats a real edit from another device.
Fix: skip the upsert when title/due/dueTime are unchanged; never send
`plan:null` over a live plan.

### 2.4 Deleting an item leaves its Google event(s) behind [code] WRONG
`js/gcal.js:541` drops an outbox op whose item is gone; `js/editor.js:438`
deletes with no push; "All of them" pushes *after* `deleteItem` → no-op;
`sweepDone` never pushes. Fix: queue a delete op carrying `gcalId`/`gcalIds`
before the item is removed and act on it in `pushNow`.

### 2.5 Series push interrupted mid-way duplicates events [code] WRONG
`js/gcal.js:516-518` writes `item.gcalIds` only after the loop; a 403 rate
limit on POST 9 of 15 retries the first 8. Fix: commit ids after each create.

### 2.6 Loop breaker false positive with two tabs [code] UX
`store.js:206` adopts the other tab's cursor via `storage`; `cloud.js:348`
counts the resulting quiet pushes; five glances at the idle tab halt sync.
Fix: count an `external` save as an edit for the breaker.

### 2.7 Smaller
- `settings.js:160,171` flips `cloud.enabled` on before sign-in succeeds.
- `cloud.js:381` `currentHashes()` taken before the await: a local edit during
  the pull is overwritten by the remote row.
- `cloud.js:504` a live row refused for a tombstone is kept locally and never
  re-pushed.
- `gcal.js:86` token client has no `error_callback`; a blocked popup leaves
  `api()` pending for ever, status "Connecting…", spliced outbox ops lost.
- `gcal.js:170` every 410 is read as "sync token expired"; a 410 on DELETE
  of an already-gone event re-queues for ever.
- `cloud.js:652` `resetClient()` leaves the old client's listeners and channel
  alive; `start()` stacks `onAuthStateChange` listeners on each sign-in.
- Export includes `cloud.url/anonKey/cursor` and `gcal.clientId/syncToken`;
  importing another device's file installs its cursors.

## 3. Calendar grids (Week and Overview)

### 3.1 23:00–24:00 is drawn below the grid [browser] WRONG
Default `dayEnd` 23 ends the grid *at* 23:00. A block at 23:00 (`top: 832px`
on an 832px body), a class 22:30–23:45 (overflows), and any 23:15+ tap-created
block are drawn under the last gridline in blank space (`A-week-bottom.png`).
Fix: draw through `dayEnd` inclusive (24 rows for 7–23), or clamp blocks
into the grid.

### 3.2 A class or block crossing midnight is drawn as a sliver [browser] WRONG
Schedule slot `23:30–00:45` → `classesOn` returns it, Week draws it 18px tall
(negative span clamped). Fix: split at midnight or reject `end <= start` in
the schedule editor.

### 3.3 Week never follows the day [browser] WRONG
`js/views/week.js:15` `let anchor = today()` at module load. Clock mocked
Sat 23:50 → Sun 03:05, the 30s tick redrew: title still "Aug 30 – Sep 5", no
`today` column. A PWA left open shows last week with no today until "Today"
is pressed. Fix: re-anchor when `today()` leaves the shown week (or when the
day changes and the user has not navigated).

### 3.4 Tray drop plans the task wherever the pointer was [browser] WRONG
`week.js:322-350`: `hit()` always returns a column and `snap()` clamps, so
`pend` is set on the first move and `onEnd` commits it; `draggable`
(`ui.js:169-175`) fires `onEnd` on `pointercancel` too, no Escape. A 20px
wiggle released over the tray planned `2026-08-30 23:45`. On the phone
`.tray-item { touch-action: none }` (`css/app.css:478`) turns a swipe to
scroll the tray into a drop: seen `Planned for Sun Aug 30 4:15pm`.
Fix: set `pend` only inside a `.daycol` rect within `dayStart..dayEnd`;
cancel on `pointercancel`/Escape; require a hold on touch like `dragBlock`.

### 3.5 Tap-to-create prompt closes itself on touch [browser] WRONG
`js/timegrid.js:439-447` opens the modal inside `touchend`; the browser's
synthesized click lands on the new `.scrim` and closes it. Seen on Week and
Overview (`.modal` gone at 800ms). Fix: open on the next tick and swallow
one click, or ignore scrim clicks for ~400ms.

### 3.6 Tap/double-click at 23:15+ makes a block past midnight [code] WRONG
`timegrid.js:446`, `overview.js:233`, `week.js:203` hard-code `mins: 60`
without a `dayEnd` clamp; `dragCreate`'s `sweep()` clamps.

### 3.7 Two now-lines on Week [code] LOW
`week.js:196` places `.now-line` and moves it; `week.js:229-233` also appends
a static `.nowline` that drifts. Drop the second.

### 3.8 Week drags not clamped to the visible range [code] LOW
`hit()` yields minutes before `dayStart` over the all-day rail; `moveBlock`
gets no `dayEnd`. A block can be dropped where Week cannot show it.

## 5. Dialogs, focus, keys

### 5.1 Every modal autofocuses its own ✕ button [browser] WRONG
`js/ui.js:55` `el.querySelector('input, textarea, button')` — the header's
Close button comes first in DOM order. Consequences seen: after drag-create,
typing a name goes nowhere and **Enter closes the prompt without creating**;
Keys modal same; **Search opened with `/` never receives typing** because
`search.js:125` focuses at 0ms and the modal steals it at 30ms. Fix: focus
the first control inside `.modal-b`, else the first footer button.

### 5.2 Escape in a confirm also closes the editor behind it [code] WRONG
`ui.js:242-246` `stopPropagation()` does not stop `app.js:482` on the same
`window`. Use `stopImmediatePropagation()` or check `openModal` first.

### 5.3 Editor commits are untagged; the page under the panel goes stale [code] WRONG
`js/editor.js:48-72` `set()` and `actions.js:31` `tickItem` commit with no
`source`; `app.js:600-603` redraws only for listed sources; `closePeek()`
does not navigate. Tick in the panel, close → row still unticked. Fix: tag
`{ source: 'editor' }` or navigate on close.

### 5.4 Sidebar semester name is written once at boot [browser] LOW
`app.js:593`; rename in Settings → `#sem-name` still "Fall 2026".

### 5.5 Shortcuts fire while a modal button has focus [code] LOW
`n`, `/`, `t`, digits run with a confirm open; `/` replaces it with search.

## 7. Repeats and selectors (`js/store.js`, `js/repeat.js`)

- **"This and after" on the first occurrence leaves a ghost series** [code]
  WRONG. `endSeriesBefore` `:716-723` / `splitSeriesAt` `:732-748`: `until`
  ends up before the anchor, `repeatDates` yields nothing, the row stays in
  `state.items`, is listed by `nextForArea`, counted by `categoryLoad`, and
  syncs for ever. Treat `key <= first` as delete-all / delete the old row.
- **`upcoming()` returns occurrences moved out of the window** [code] WRONG.
  `:409-415` via `occurrencesBetween` `:305-308`: an occurrence moved to Dec 1
  shows in the next-two-weeks list; one moved to the past shows in both
  upcoming and overdue. Filter on the effective date.
- **`cardToItem(…, {as:'timed'})` sets `due`, `dueTime` and `plan`** [code]
  `:905-911` — drawn twice (deadline and block).
- **`upsertItem` with a stale id resurrects it as an Untitled row** [code]
  `:655-667` `...patch` last. Editor left open while a pull deletes the item,
  then any keystroke. Return null when `patch.id` names nothing.
- `repeat.count: 0` means unlimited (`repeat.js:100`); string `days`
  concatenate in `addDays`. Tick-then-untick leaves `{done:false}` in `ex`
  for ever (`:836-838`); toggling an id the rule never named creates junk
  `ex` keys (no `isRepeatDate` check).
- Empty title saved as `""` renders a blank row in the area's Open list.

## What was checked and held up

Windows classic scrollbars: week head/body/all-day columns align (10px bar
inside `.week-scroll`, rail under its max height). Keyboard shortcuts do not
fire while typing. Undo/redo after quick add. `today()` at 02:59 is still
yesterday; `carryForward` moves the end-of-day line into the next morning's
focus. DST-end and DST-start weeks draw seven days, one standup each, and the
now-line at the right height. Corrupt JSON, unknown categories, `null`
titles, bad times, bad repeat rules: every route still draws. Long-press
drag on touch moves a block; tap opens it; edge swipe opens the menu. Export
downloads; second tab receives a `storage` update.
